## 2. 核心校准模型（v4.0 · 题量置信 + 严依赖）
- 锚定：稳定考到 ~125 分（满分 150）= 每个知识点 100% 掌握。
- 难度 5 档及满分贡献：★基础=10% / ★★基础应用=15% / ★★★中档=25% / ★★★★综合=30% / ★★★★★压轴=20%（合计 100%）。
- 进度公式：`M = sum( w_i * c(n_i) * s(p_i) * d_i )`
  - p_i = 第 i 档正确率。
  - `s(p) = p^1.5`（稳定函数）：偶尔做对不算会。80% → 71.6%，50% → 35.4%。
  - `c(n) = n / (n + 8)`（题量置信）：1 题只算 11.1%，5 题算 38.5%，20 题算 71.4%；防止 1 题定档。
  - `d_i` = 基础依赖系数。d_1=1；i≥2 时取低档 s(p) 的几何平均，**低档未测按 10% 硬惩罚**，高档会被大幅打折。
  - 未测档自身贡献为 0。
- 100% 含义：该知识点每档都有足够题量且稳定全对，低档扎实、高档也能做。
- 自动计算：`生成脚本/compute_progress.py` 读取 `题库.md` 自动算出全局 M；知识点图谱中的章节进度按小知识点平均计算。
- 状态标签：⚪ 未测/起步（M<1%）/ 🟡 掌握中·起步（1%≤M<25%）/ 🟡 掌握中（25%≤M<50%）/ 🟢 掌握较好（50%≤M<80%）/ 🟢 已掌握（M≥80%）；有做错记录标 🔴 薄弱·需巩固。

## 9. 两类来源分类 + 拍题入库流程（重要）

### 9.0 写入时机（最高优先级 · 用户体验铁律）
- **白天用户发题时：只解答 + 在对话里记住，绝不立刻写 md、绝不跑 PDF。**
  - 用户边刷题边等答案，任何写文件/生成 PDF 的动作都会拖慢他，必须克制。
  - 收到题 → 立即给解析/判定 → 把"题面/考点/难度/来源/出处/结果/复盘"先记在**本次对话上下文**里（或临时记一份草稿），不落盘。
- **只在用户明确说「总结今天 / 总结一下今天的知识点题目 / 今天做个总结」时，才一次性批量落盘：**
  1. 把白天攒下的所有题写入 `题库.md` 与 `做题档案.md`；
  2. 刷新图谱进度（必要时重跑 `compute_progress.py` 取数）；
  3. 跑 `gen_pdfs.py` 同步四份 PDF。
- 一句话记忆点：**白天=答+记（内存）；总结=写.md+刷PDF（落盘）。**

### 9.1 来源分类
题库与做题档案里每题都带「来源」标记，用表情区分两类：
- 🟦 **小柒出题**：我主动出的题（基础/进阶/压轴 Word 题集）。
- 🟧 **我拍的题**：用户拍照/截图发来的题（来自辅导书、卷子等），**不是我出的**，需特殊标注。

### 9.2 收到用户拍的题时的标准动作（白天只做 1–2，落盘推迟到「总结今天」）
1. 分析该图的**知识点**与**难度**（★~★★★★★，对应 L1~L5）。
2. 问清或记录**出处**：用户若说「线代基础660题 / 李永乐线代严选题」等，记到「出处」；没说则记「（未说明）」。
3. （落盘时做）写入《题库》一行：日期 / 题号（自取，如「线代660题 P23」）/ 考点 / 难度 / 结果（给了答案填✅❌，没给留空）/ 来源=🟧 / 出处 / 档案位置。
4. （落盘时做）在《做题档案》建对应条目：题面取自照片 + 我的分析，末尾「题库位置」指回题库。
5. （落盘时做）刷新《题库》底部「归纳」：按来源（🟦 / 🟧）+ 按出处 两组计数。
6. （落盘时做）跑 `gen_pdfs.py` 同步 PDF。

> 两种来源在图谱进度计算上**一视同仁**（都按难度×正确率计分）；分类只是为了区分"谁出的题"和便于按出处归纳薄弱辅导书。
